# T05 · 授权审查与禁止旧协议接管

状态：in_progress。已完成 T05.a（威胁边界核验与旧入口关闭），尚未实现 T05.b（逐设备授权与 QUIC 连接绑定）。

证据基于 SOURCE_AUDIT：客户端有 pinning，但服务器不要求客户端证书；入站数据回调丢失连接实例信息，只带地址；部分输入后续包依赖地址 TTL；组 secret 与自报 controller 标识用于授权；发现消息可以刷新已配对证书。不能把这条路径包装为已完成逐设备、逐连接授权。

按交接包 02 §5.1 的要求，未验证授权前真实 LAN 注入不可激活。当前 fork 将旧 V1 LAN 路径固定关闭：启动发现返回明确错误，不监听 LAN；输入捕获/接收、剪贴板后台返回 idle 和中文说明；输入/剪贴板/文件接收入口以及文件发送命令均拒绝。不会因打开开发版本自动请求输入权限、启动旧捕获或同步用户剪贴板。

这不是 T05 完成，也不是 V2 授权实现。`LEGACY_LAN_DATA_ENABLED` 不应在下一轮被简单改成 true；应新增经验证的 V2 连接路径，复用已审查的平台基础。旧代码保留以对照迁移，Windows 没有被替换为空实现。

## 下一步 T05.b / ADR-005

1. 冻结逐设备信任模型：持久证书不可由发现消息更新；双方人工配对确认。
2. QUIC 回调携带不可伪造的连接代际和认证 peer context，而非 SocketAddr 代理身份。
3. 在固定服务端证书的 TLS 连接内证明客户端持有对应逐设备凭据，或采用经过审查的双向证书设计；不自造加密算法，不把组 secret 当设备身份。
4. 认证前仅允许限长、限并发的配对/协商；禁用真实数据。0-RTT 不承载输入。
5. 编写未知 peer、证书变化、错误角色、连接借用的负例，再接入 T06。A10–A12 尚未达到完整验收，不标 pass。

验证：新增旧 LAN 禁用检查先失败再通过，当前隔离测试 7/7；Mac 库回归 127/127。测试保留旧协议纯函数 fixtures，但没有启用旧协议或调用真实系统注入。Windows 仍 pending_environment，LOL optional_not_run。
