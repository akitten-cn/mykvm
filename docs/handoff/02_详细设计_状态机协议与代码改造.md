## 2. 纯逻辑与平台接口

将“应当做什么”与“系统调用如何做”分开，使 Mac 能测试 Windows 路由策略。

```rust
// 拟议接口：名称可调整；语义和非阻塞要求不可丢失。
pub enum RouteAction {
    GoRemote { peer_id: PeerId },
    GoLocal { reason: ReturnReason },
    SetGameMode { enabled: bool },
}

pub trait CapturePort {
    fn prepare_capture(&self) -> Result<(), CaptureError>;
    fn activate_capture(&self, session: SessionId) -> Result<(), CaptureError>;
    fn request_local_restore(&self); // 不等待网络或 GUI
}

pub trait InputQueuePort {
    fn try_enqueue_critical(&self, event: CriticalFrame) -> Result<(), QueueError>;
    fn replace_latest_motion(&self, motion: MotionFrame);
}

pub trait InjectorPort {
    fn readiness(&self) -> InputReadiness;
    fn post_event(&mut self, event: MappedEvent) -> Result<(), InjectError>;
    fn release_owned(&mut self, session: SessionId) -> ReleaseReport;
}
```

约束：这些接口不在操作系统回调内做等待。上例 `prepare_capture` 若底层需要线程交互，应在准备态异步调度，不能从钩子回调直接同步调用。

测试提供 `FakeCapturePort`、`FakeInjectorPort`、`FakeClock`、`FakeTransport`。模拟器默认只记录抽象事件，不监听真实键盘、不注入真实桌面、不读真实剪贴板。

Mac 原生 `CGEventPost` 等调用完成不等于目标应用已执行用户动作。`applied_seq` 的含义只到“适配器完成本次提交/账本处理”，不能包装成窗口动作成功 ACK。

## 3. 输入路由状态机

### 3.1 状态

```rust
pub enum RouteState {
    LocalDesktop,
    LocalGame,
    PreparingRemote {
        peer: PeerId,
        request: RequestId,
        deadline: Instant,
        previous_local: LocalMode,
    },
    RemoteActive {
        peer: PeerId,
        session: SessionId,
        return_mode: LocalMode,
    },
    ReturningLocal { reason: ReturnReason },
}
```

`Suspended`、`Locked`、`PermissionDenied` 作为运行能力状态，不应伪装成远程成功。Mac receiver 的会话状态与 Windows 源端路由状态是两套对象，不能共用一个 `remote_active` 布尔值。

### 3.2 转移规则

| 当前状态 | 事件 | 动作/下一状态 |
|---|---|---|
| LocalDesktop/LocalGame | GoRemote | 保持本地控制，开始认证/准备；进入 PreparingRemote |
| PreparingRemote | 重复 GoRemote 同设备 | 忽略重复，不重复创建连接/钩子 |
| PreparingRemote | Ready + 组合键释放 + 焦点准备成功 | 请求 Commit；等当前请求的 CommitAck 后激活 |
| PreparingRemote | 超时/权限失败/GoLocal | 取消请求、释放本机自有资源；回原本地模式 |
| RemoteActive | GoRemote 同设备 | 幂等无副作用 |
| RemoteActive | GoRemote 另一设备 | 首版拒绝并提示先返回，不实现多设备无缝串跳 |
| RemoteActive | GoLocal/健康失败/队列故障 | 先本地恢复，再通知 EndSession |
| 任意状态 | 紧急返回 | 设置本地覆盖标志；所有输入钩子立即优先放行 |
| Local* | 旧 Ready/CommitAck/End/Pong | 不改变本地状态，不复活旧会话 |

### 3.3 本地紧急通道

路由 actor 不能成为唯一的逃生入口。Windows 热键/钩子入口持有一个轻量原子 `local_override`；紧急返回首先设置它，再通知状态机。

钩子开头读取该标志：为真则放行本地输入，不继续遍历目标、序列化或发送。光标隐藏、自己持有的裁剪/解耦资源由所属平台线程清理，清理动作不得等待网络。

这不保证操作系统挂起、进程被强杀或驱动故障时还能运行代码。设计要说明边界，不靠无限重启/SYSTEM 服务伪造“绝对恢复”。

### 3.4 切换时按键处理

普通 GoRemote 等待物理组合键与按钮释放；等待最多约 1500 ms（可调初值），超过则留在本机。持续按键不能假装释放后直接远控。

Remote→Local 不等待网络 ACK。热键识别前已经发到 Mac 的 Ctrl/Alt，必须由真实账本释放；不能简单吞掉 key-up。不要为了识别热键长期缓存所有 Ctrl/Alt 组合，破坏普通开发快捷键。

按键自动重复不得重复触发控制切换。状态准备中按 GoLocal 优先取消；晚到的 Ready/CommitAck 根据 `request_id` 与会话代际丢弃。

## 4. Windows 适配与游戏策略

### 4.1 首要代码入口

在冻结源码中定位：`windows_mouse_proc`、`windows_keyboard_proc`、`handle_windows_mouse_move`、`start_input_capture`、`request_screen_switch_from_point`。这些是旧审查中的定位线索，函数签名必须本地核验。

本地游戏态优先卸载不需要的鼠标钩子。若不能立即安全拆开，先实现最短本地放行路径，并在任务报告中明确“快速路径已实现，完全卸钩待优化”，不能把两者混为一谈。

本地游戏态不做：边缘匹配、远端屏幕列表重建、光标隐藏/归中、逐移动事件序列化、逐事件日志、发送网络、等待互斥锁。Windows 输入钩子超时可能被系统移除，慢工作必须移出回调。[S13]

### 4.2 热键协调

本地态复用/核验已有 global-shortcut 插件或注册机制，避免再建立一套冲突入口。远程态在吞键之前识别本地控制热键，派发同一个 `RouteAction`。每次物理组合键按压只有一个 action ID，系统热键消息与低级钩子触发不得重复执行。

F12 不作默认值。用户自选冲突热键时报告“注册失败”，不静默换键。[S10]

### 4.3 焦点策略

`ConservativeFocusPolicy` 是首版默认值：只因用户明确按下切换键才尝试一次焦点交接；失败则停止远程激活并提示先 `Alt+Tab`。不得在定时器中不断抢前台。

可以使用不含 WebView 的轻量原生控制窗口作为焦点接收者。窗口不能覆盖显示器或持续渲染；实现应记录前台窗口变化供诊断，但不记录敏感窗口标题。

`SetForegroundWindow` 有系统限制，普通鼠标事件截断也不等于所有 Raw Input 都被隔离。[S11][S12]

禁止方案：注入游戏、驱动绕过、改反作弊、强制全局 `ClipCursor(NULL)` 循环、默认提权、自动禁用其他程序输入。

**该策略的接口、回退、状态和 Windows 代码在 Mac 阶段照常实现；LOL 的效果验证是非阻塞可选项。** UI/版本说明不得把尚未测试的模式标成“已验证兼容 LOL”。

### 4.4 鼠标回报率

本机游戏鼠标不因本项目全局降低回报率。远程鼠标发送可以独立按最新位置合并，例如初始 125 Hz，配置上限待测试确定。原始捕获事件序列不等于必须每个事件都发一个网络包。

## 5. V2 连接与会话协议

### 5.1 信任边界

上游审查快照使用服务端证书 pinning，但传输客户端配置有 `with_no_client_auth()`；这只能证明该层不是 mTLS，不能据此断言应用层完全无授权。[S02]

T05 必须核验 `lib.rs` 的配对、`pair_secret`/设备权限验证与实际接收入口。优先复用已证明有效的每设备配对凭据，不新造加密算法。

实现契约：

1. 发现地址只用于定位；从持久配对记录取得期望证书与设备身份，不能每次信任发现广播的新证书。
2. 先在已校验服务端身份的 TLS 连接中完成现有应用层客户端授权，再产出 `AuthenticatedPeer`。
3. `AuthenticatedPeer` 绑定具体 QUIC 连接实例、持久 peer、信任版本和角色权限；不只携带 SocketAddr。
4. 若现有 `pair_secret` 是多个设备共用的群组密钥，不能把它当成逐设备身份。必须改为每对设备授权或用经审查的双向证书方案，并记录 ADR。
5. 初次配对始终需要人工确认；未经授权只允许有界配对协商，不接受输入、剪贴板或文件。
6. 不启用会重放输入的 0-RTT 路径；旧版本不自动降级成未授权输入协议。

若尚未完成授权审查，可以继续纯模拟开发，但真实 LAN 注入入口必须保持不可激活。不是要求用户运行 LOL。

### 5.2 协议边界

新协议使用明确主版本/能力协商，例如 `protocolMajor = 2` 与独立 ALPN/魔数。名字在实施时固定。只支持本 fork 两端之间的 V2；不承担与所有上游旧版输入协议混用的兼容成本。

以下字段为拟议线路语义：

```text
ConnectionContext
  authenticated_peer_id
  connection_generation           本进程中连接唯一代际
  local_boot_id / remote_boot_id   进程启动时随机生成
  trust_revision

SessionId
  controller_boot_id
  receiver_boot_id
  random_session_nonce            每次新控制会话随机生成

ControlFrame
  Hello(version, capabilities)
  Prepare(request_id, target_display, policy)
  Ready(request_id, receiver_boot_id, input_readiness)
  Commit(request_id, session_id)
  CommitAck(session_id)
  EndSession(session_id, reason)
  Ping/Pong(session_id, heartbeat_seq, highest_applied_seq, injector_progress)
  Reject(error_code)

CriticalFrame
  session_id
  seq                             本会话可靠事件单调序号
  pointer_snapshot                鼠标/按钮/滚轮使用的坐标与 motion_seq
  event                           Key / Button / Scroll

MotionFrame
  session_id
  display_id / layout_revision
  motion_seq
  required_reliable_seq
  absolute_x / absolute_y
```

协议长度前缀必须在分配前检查，使用 checked arithmetic，未知版本、非法尺寸、过大字段、未知枚举和未授权动作明确拒绝。

### 5.3 通道组织

| 通道 | 用途 | 要求 |
|---|---|---|
| 小型可靠 control stream | Prepare/Commit/End/健康/ACK | 独立于大载荷；限制帧长/频率 |
| 每会话持久可靠 input stream | key/button/scroll 的状态事件 | 有序；不静默丢 key-up |
| QUIC datagram | 最新绝对鼠标位置 | 序号/依赖；可以淘汰旧位置 |
| 独立 bulk stream | 可选文本/图片剪贴板 | 限大小、并发和预算；游戏模式默认不发大图片 |

输入/控制流不能使用现有“等整个 stream 到 EOF 后一次解析”的处理函数直接冒充持久消息流；要新增有界逐帧解析路径。上游 `spawn_stream_reader` 的大载荷读取方式仍可为旧 bulk 接口保留，但接收并发/字节预算需补查。[S02]

一个 QUIC 连接上的不同流仍共享网络和拥塞资源。分开任务不等于严格 QoS；大图片必须限速或暂停，不能只靠 task 优先级。

### 5.4 准备与激活

```text
Windows 本地态
→ 认证连接可用
→ Prepare
← Ready（仅准备，不注入）
→ 等键松开 + 本地焦点准备
→ Commit
← CommitAck
→ 当前请求仍有效且未紧急返回时才启用捕获
→ RemoteActive
```

准备阶段不能吞本机键鼠然后无限等网络。Prepare/Commit 总超时初值 2500 ms；用户操作与网络情况可调整。对端 Ready 并不意味着系统中的所有目标应用都保证接收注入。

超时、取消、权限变化、不同 boot ID 或重复 Commit 均须安全处理。取消后晚到的 ACK 不得激活。

### 5.5 本地返回

1. 设置本地覆盖/停止路由状态，先放行本机输入。
2. 由平台线程释放自己的光标状态和捕获资源。
3. 撤销该会话发送队列，异步发送高优先级 EndSession；必要时关闭该会话/连接。
4. 对端 EndSession 或租约超时后释放账本。
5. 新 GoRemote 必须创建新的 SessionId；不得自动恢复旧的 RemoteActive。

第 1 步绝不等第 3 步的网络进展。

### 5.6 健康检查

设计初值：远程活跃时约 300 ms 一次健康消息，1500 ms 无有效进展则结束；本地闲置时不沿用高频会话心跳。底层 QUIC keepalive 不能替代应用注入健康。

心跳必须来自当前会话、当前连接，且能反映注入工作队列仍在推进。仅网络线程回 Pong 而注入线程已阻塞，不能继续显示健康。

接收超时逻辑不能和图片解码共用一个可长期阻塞的执行路径。平台清理本身失败时返回明确错误并关闭远控，不重试成无限注入循环。

### 5.7 点击、拖拽与位置乱序

维护 `highest_applied_reliable_seq`、`motion_floor`、`latest_pending_motion`。

- 每次按钮/滚轮事件携带采样时的真实位置与 motion_seq，先应用该位置再操作按钮。
- datagram 的 `required_reliable_seq` 未应用时只暂存最新位置，不能抢先应用拖拽移动。
- 可靠事件应用后更新 motion_floor，忽略更旧的位置包，避免点击后被迟到包拖回旧位置。
- 最新位置槽位只保存一个绝对位置；若上游是相对位移，先累计再合并，不能丢掉相对距离。
- 新布局版本、显示器拔插、非法坐标范围要求重新获取显示信息；不能把 Windows 物理像素直接当 Mac Retina 坐标。

首版支持一个指定 Mac 显示器，保留上游布局能力但不扩大多设备跨跳范围。显示映射统一坐标单位与边界，覆盖负坐标、缩放、Retina 和窗口模式差异的纯逻辑测试。

## 6. 可靠队列与账本

### 6.1 有界发送

可调初值（实施后应写配置常量和测试，不是当前实测）：

| 项目 | 初值 |
|---|---|
| control 帧长 | 最大 16 KiB |
| input critical 队列 | 最大 256 个事件，另加字节限制 |
| motion 槽位 | 最新位置 1 个；datagram 载荷目标不超过约 1000 B，实际按协商 MTU |
| 单会话未解析帧 | 有界，不按网络自报长度无限分配 |
| 剪贴板发送/接收并发 | 每方向各最多 1 个，并受全局内存预算约束 |

关键队列满：记录限流指标、结束会话、返回本机；不能丢掉 key-up 后继续“正常”。大量鼠标事件不能挤走紧急动作，紧急返回不是普通队列末尾的一个消息。

上游当前有 `UnboundedSender`；这是要改造的具体位置。已有 stream semaphore 保留其作用，但它不限制入队前持有的大 payload 总量。[S02]

### 6.2 接收按键账本

账本属于一个已授权会话，记录已提交的映射后按键/按钮、必要标志、源物理键标识，以及用于释放的原映射。自动重复不新增重复条目。

```text
源端 virtual key + scan code + extended/location
  → 选定键位规则
  → 目标 Mac key/flags
  → 提交系统注入
  → 更新本会话账本
```

两个源键映射到同一目标键时要考虑引用计数/按下所有权，避免松开一个就提前释放另一个。

ReleaseAll 必须真实提交 key-up/button-up；不能只是清空 Rust 集合。正常结束、网络中断、权限撤销、禁用、正常退出走同一路径。

已终止 SessionId 的迟到 End/数据/心跳不影响新会话。接收端进程崩溃或被强杀后无法保证立即执行释放；此限制必须出现在最终交付报告，不能写“强杀已绝对防卡键”。

## 7. Mac 键位与输入法

核对 `inject_key`、`windows_vk_to_mac_key`、`windows_vk_to_mac_flag` 及实际调用路径。

默认预设：Windows Ctrl→Mac Control；Win→Command；Alt→Option。另提供显式 Ctrl/Command 互换预设。不要根据当前应用动态偷偷换键。

按下时冻结映射，松开时使用旧映射；修改设置只作用于之后的新按键。中文输入由 Mac 输入法处理，不把键盘事件变成高速粘贴文本。

测试包含左右修饰键、Ctrl+C 中断、Command+C/V、Option+方向键、Shift+选区、数字小键盘、OEM 标点、Caps Lock、输入法切换与自动重复。

无法可靠表示的 Fn/Globe/亮度等硬件特殊键不承诺完整转发。可以配置普通组合键替代明确的系统/应用动作，但不得在配置里写一个“Fn 已支持”占位选项。

Mac receiver-only 模式不启动不需要的本机捕获钩子或光标归中循环。监听本地键盘若会增加权限，只在需要本地接管功能时单独设计，不把它伪装成零成本。

## 8. 原生剪贴板设计

### 8.1 后端和结果

Windows 使用 `AddClipboardFormatListener` 事件触发读取，剪贴板忙时做短暂有界重试。[S14]

Mac 使用进程内 NSPasteboard 或已验证的 arboard 读写；先取 `changeCount`，变化再读。初始轮询可在活跃时 250 ms、长时间无变化时退到 1000 ms，重连/手动重发立即检查，不持续启动 pbpaste/pbcopy。[S03][S15]

```rust
pub enum ClipboardReadResult {
    Unchanged,
    Content(ClipboardContent),
    Unsupported,
    TemporarilyUnavailable,
    Error(ClipboardError),
}
```

空、失败、不支持、权限异常不是“对端应该清空”。首版不同步显式清空，除非后续新增单独开关与测试。

### 8.2 双向同步和回声

每个真实用户复制事件产生 `(boot_id, local_seq, origin_peer, content_digest)`；本机系统剪贴板版本只在本机使用，不能直接比较 Windows 与 Mac 的系统序号。

对端写入后记录自身系统版本与摘要，识别这次写入产生的回声；紧接着用户再复制不同内容仍须传播。禁止用“收到远程后屏蔽 1 秒所有复制”代替真实回声识别。

两个设备同时复制时采用明确的确定性冲突策略。建议使用 Lamport 计数加稳定 peer ID 做排序；收到有效远端操作更新观察值，但远端写入本身不产生新的本地操作。相同操作幂等应用。时钟与操作表有界，只服务两台已选定设备，不能增长成无限历史库。

读/写之间本机又发生新复制时，再次核验本机版本并按冲突规则处理，避免旧远端任务晚执行覆盖新本地内容。

首次连接和重新连接默认不自动把旧剪贴板推给对方；等待新复制或用户手动重发。这样避免启动软件就把另一台已有内容覆盖。

### 8.3 大小与优先级

上游文本上限为 256 KiB，图片解码 RGBA 预算为 32 MiB。[S03] 首版可将文本默认上限调整为 1 MiB，以满足长代码/日志，超限必须提示，不默默截断。

图片默认关闭，用户可以开启；最大解码大小不超过上游 32 MiB。要在解码前检查像素乘法溢出和尺寸，在 base64/复制/解码的每一阶段计算峰值预算。可将全局批量任务预算初定为 128 MiB，但必须包含传输缓冲、base64 额外字节和解码副本，不能只计算最终图片。

第一版不强制更换图片编解码，以减少范围；若现有读法不可在分配前限界，应禁用不安全图片路径或单独修复，不能只在分配后判断超限。

游戏模式默认暂停大图片。文本也是 bulk 工作，不和输入共用同步等待路径。无法保证不同流完全不竞争带宽，应实际测量并提供暂停/取消。

### 8.4 隐私

只向选定已配对设备同步。日志不保存正文、内容摘要关联历史、完整按键流或密钥。来源排除/敏感内容标记仅为尽力而为，不承诺所有密码都能自动识别。提供一键暂停和手动同步。

## 9. 后台运行与界面

后台运行时由 Rust 拥有所有服务。设置页是可销毁的客户端，不在 React `useEffect` 中启动唯一网络循环、注册关键热键或担任心跳源。

Tauri 静默启动采用 `create: false` 或同等按需建窗逻辑，区别于只设 `visible:false`。现有窗口销毁/重建逻辑先核验再复用。[S06][S16]

Windows release 无控制台属性已经存在；检查新增 helper 的启动标志，不能为本次新增常驻终端。Mac 保留菜单栏项目，关闭设置不退出后台；明确“退出”才停服务。

用户登录自启默认需用户启用，不自动安装系统守护服务。主线程缺窗口也应保持 Tauri/平台消息循环需要的对象。设置页打开时最多约 1 Hz 推指标，关闭后停止 UI 推送；状态变化允许事件通知。

## 10. 配置、安全与升级隔离

fork 的 productName、identifier、配置、锁、自启项和更新源必须一致。可先用内部名 `MyKVM Local` / `local.mykvm.gaming`；最终名称写入基线，不冒充上游。

禁用上游 updater 的主动检查、UI入口和安装路径；仅修改 endpoint 不够。保留依赖或移除依赖均以能编译、权限清晰为准。后续自建更新需独立签名密钥和用户授权，不属于本轮默认自动化。

NSIS hooks、Windows helper、Mac install/sign 脚本需逐项核对副作用。不能让 `npm run ...` 意外安装 SYSTEM 服务、覆盖 `/Applications/mykvm.app` 或修改用户钥匙串信任。[S06][S08]

Tauri capability/IPC 仅开放所需窗口与命令。参数从 UI 到 Rust 同样校验；设备名、网络包、剪贴板文本不得拼进 shell 命令。诊断不执行远端发来的内容。

## 11. 错误码与诊断

建议结构化错误：

```text
E_PEER_UNTRUSTED / E_IDENTITY_CHANGED / E_PROTOCOL_MISMATCH
E_INPUT_PERMISSION / E_RECEIVER_NOT_READY
E_HOTKEY_CONFLICT / E_HANDOFF_TIMEOUT / E_KEYS_HELD
E_FOCUS_UNAVAILABLE / E_SESSION_EXPIRED / E_CRITICAL_QUEUE_FULL
E_CLIPBOARD_BUSY / E_CLIPBOARD_UNSUPPORTED / E_CLIPBOARD_TOO_LARGE
E_CAPTURE_FAILED / E_RELEASE_INCOMPLETE
```

UI 提供中文说明与可操作提示。日志仅记录时间、任务/事件类别、脱敏 peer、会话代际短标识、错误码、队列深度/长度和状态转移，不逐键落盘。

开发测试里的输入事件可用虚构 fixtures 断言；不能用真实用户键入内容充当共享调试日志。

## 12. Mac 优先实施约束

所有核心状态、协议与调度测试必须不依赖 LOL、不依赖第二台机器、不默认注入真实桌面。Windows 平台代码通过 `cfg(target_os = "windows")` 正常实现，Mac 编译无法覆盖的部分交由可用的原生 CI。

本文件里的安全状态和失败回退是代码实现要求，**不是 LOL 实机验收关卡**。无 Windows/LOL 环境不阻止完成后续剪贴板、UI、打包和文档任务。
