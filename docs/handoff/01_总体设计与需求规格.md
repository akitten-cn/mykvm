# MyKVM Fork 总体设计与需求规格

版本：2.0 · Mac 优先开发 · 2026-09-07

## 1. 产品定位

这是一个针对两台自用电脑的输入共享改造，不是远程桌面、云控平台或全功能商业 KVM。

```text
使用环境：
Windows 游戏电脑 —— 物理键盘、鼠标
       │  已配对的局域网连接：输入 + 可选剪贴板
       ▼
M4 Mac mini —— Codex / 终端 / IDE / 浏览器

显示器 1 直连 Windows；显示器 2 直连 Mac；不传画面。

开发环境：
M4 Mac mini —— 源码、模拟器、自动化测试、Mac 构建
       └── 可用时使用 Windows 原生 CI 检查另一平台
```

用户确认的现象：Deskflow 发生过 Windows→Mac 剪贴板为空，关闭 Windows 守护进程后恢复；LOL 选英雄时不能跨屏；使用 RustDesk 时感觉游戏掉帧。这些是用户的实测经历，不等于已经定位所有底层原因。

### 2.1 首版不做

屏幕捕获/视频编码解码、音频转发、文件拖放改造、互联网穿透、中转服务器、移动端、Linux 新功能、Windows 安全桌面控制、自动代打/宏、游戏注入、内核驱动、反作弊规避，以及跨项目输入引擎拼装。

对上游已有而本次不用的能力优先“配置/功能开关不启用”，不要未经审查大面积删除。必要的文件传输禁用覆盖 UI、命令入口、网络接收和后台任务，不能只藏一个按钮。

### 2.2 桌面与游戏模式

- **桌面模式**：可以保留已有边缘切换；方向布局只影响桌面体验。
- **游戏本地模式**：不边缘切换；使用明确热键；不持续重建显示器布局、鼠标归中、逐事件发网络或写日志。
- **远程控制模式**：Windows 控制 Mac。共享光标/输入不要求 Windows 游戏继续接收任何事件；焦点交接失败时保守回到 Windows 并提示 `Alt+Tab`。

默认提供手动游戏模式开关。进程检测只可作为提示或可选辅助，不把进程名匹配写成安全/兼容性保证。

## 3. 首版功能交互

### 3.1 热键

| 动作 | 提议默认值 | 行为 |
|---|---|---|
| 控制指定 Mac | Ctrl+Alt+F11 | 同目标已激活时无副作用；准备中不重复启动 |
| 返回 Windows | Ctrl+Alt+F10 | 所有状态可调用，优先本地恢复 |
| 紧急返回 Windows | Ctrl+Alt+Shift+F10 | 本地优先覆盖标志；不依赖异步路由任务存活 |

热键可修改，注册失败应显示冲突。不得默认占用 F12；Microsoft 对其有保留说明。[S10]

不同状态下系统热键与低级钩子可能互相影响，因此只设一个动作派发入口；不能只添加 `RegisterHotKey` 就认定远程态能返回。

### 3.2 切换前检查

目标已配对、协议兼容、接收端权限可用、运行时可接收、无遗留终止会话。只检查 IP 可达不够。

普通“去 Mac”要求切换组合键和鼠标按钮释放后交接。用户还在按其他键时短暂等待，超时取消，不伪造松键。紧急返回则不能等待用户松键才恢复本地；仅做必要的本次控制热键防泄漏处理。

### 3.3 UI 页面

1. **设备**：配对身份、连接状态、默认 Mac、权限与协议不兼容说明。
2. **输入**：三个热键、游戏模式、桌面边缘切换、Mac 键位预设。
3. **剪贴板**：双向文本、图片开关、暂停、手动重发、大小限制。
4. **后台与诊断**：用户登录自启、启动不显示设置、状态导出、最近错误。

托盘/菜单栏始终提供：当前控制目标、返回本机、游戏模式、暂停剪贴板、打开设置、退出。退出前正常结束会话并释放自己引入的输入状态。

## 4. 架构边界

保留 Tauri + Rust + React，第一版不换 GUI、不换 QUIC 库。现有 `input.rs`、`lib.rs` 作为接入点，逐步抽离本次真正需要的逻辑。

```text
Tauri/React 设置页（可销毁）
          │ 配置命令 / 低频只读状态
Rust AppRuntime（后台所有者）
  ├── RouteCoordinator：唯一控制状态所有者
  ├── LocalOverride：本地应急原子标志
  ├── Capture/Hotkey Windows Adapter
  ├── Receive/Inject macOS Adapter
  ├── Session + PressedLedger
  ├── AuthenticatedPeer + QUIC Connection Owner
  │     ├── 可靠输入/会话控制
  │     ├── 可合并鼠标位置
  │     └── 低优先级剪贴板
  ├── ClipboardSync + Native Backends
  ├── Config / Tray / Autostart
  └── Metrics / Redacted Diagnostics
```

原则：React 不是服务保活入口；输入钩子不等待网络/GUI/文件；图片处理不与安全释放共用阻塞路径；返回本机不经过剪贴板队列；真实授权检查不能只存在于 UI。[S02][S03][S07]

## 5. 代码策略

详细文件与接口见 `02`。新增模块是建议落点，Codex 应先核对完整源码，以最小 diff 实现。拒绝“为了目录好看”拆出大量空转抽象。

Windows 相关实现使用平台条件编译，但核心状态、队列策略、协议解码、映射和账本应可在 Mac 测试。可通过纯 Rust module + trait 假实现做到，不强制先建立一个全新独立 crate。

本次核验已确认：

- QUIC 已有非阻塞 datagram、独立 stream 任务和发送并发限制；要审查的是无界命令队列、输入事件语义、接收限制和连接生命周期，不能重做一遍既有修复。[S02]
- `main.rs` 已有 Windows release 的无控制台属性和单实例入口，任务是保留并回归，不是声称首次添加。[S05]
- 传输客户端代码使用单向证书校验并关闭客户端证书认证，不能仅凭“用了 TLS”就称为双向身份认证；上层配对授权还需完整核验。[S02]

## 6. 配置模型（拟新增/扩展）

版本化配置采用以下语义，字段名在 T00/T01 确认后落地：

```json
{
  "schemaVersion": 2,
  "role": "controller",
  "defaultPeerId": null,
  "routing": {
    "gameMode": false,
    "edgeSwitchInDesktop": true,
    "edgeSwitchInGame": false,
    "remoteHotkey": "Ctrl+Alt+F11",
    "localHotkey": "Ctrl+Alt+F10",
    "emergencyHotkey": "Ctrl+Alt+Shift+F10",
    "focusPolicy": "conservative"
  },
  "clipboard": {
    "textEnabled": true,
    "imageEnabled": false,
    "syncOnConnect": false,
    "pauseLargeTransfersInGame": true
  },
  "startup": {"atUserLogin": false, "openSettings": false},
  "updates": {"automatic": false}
}
```

Mac 的默认角色是 `receiver`。`defaultPeerId` 不填假值，首次选择后保存。默认不迁移旧信任密钥；如果需要导入，单独确认。配置迁移先备份、原子替换，保留不能理解的旧字段或明确报告，不静默重置。

## 7. 资源预算：目标而非已经测得的结果

| 项目 | 设计要求 | 验证口径 |
|---|---|---|
| 视频/GPU | 不引入视频链路；设置关闭时不持续渲染主 WebView | 源码/进程组检查，不承诺所有 GPU 计数永远为 0 |
| 本地游戏输入 | 尽量卸载鼠标钩子；无法立即拆开时最短放行路径 | 本地路径调用计数、Windows 可选实测 |
| 内存 | 队列、图片和缓存有上限 | RSS/私有内存包含子进程，长时趋势 |
| 剪贴板 | Mac 进程内读取；变化后才取内容 | 不持续启动 pbpaste/pbcopy；CPU/唤醒次数 |
| 日志 | 不逐鼠标事件写盘；错误限流 | 日志字节增长、诊断字段白名单 |
| UI | 后台运行不依赖主窗口 | 关闭设置后自动化生命周期测试 |

初始工程预算可设为：空闲进程组平均 CPU 接近闲置，10 分钟观测中争取低于一个逻辑核心的 1%；本机运行 8 小时无持续内存增长。若设备/系统口径不同，必须报告实际口径与误差，不把预算当成过测证据。

游戏 FPS、1% low 和帧时间对比是后续可选测量。没有测量时照常交付已实现的代码和预览包，但不宣传“保证零掉帧”。

## 8. 安全、权限和部署

只对人工确认配对的电脑开放输入与剪贴板。发现广播不能自动成为信任根。输入消息绑定已授权连接与会话，不以 IP、设备显示名或网络自报 ID 代替认证。

Mac 的辅助功能/输入相关权限由用户通过系统界面授权。仅在所需能力确实要求时请求对应权限；不得因为普通键鼠共享去申请屏幕录制权限作为默认步骤。

默认只做用户登录后的普通进程，不创建 SYSTEM 服务、不自动弹 UAC、不更改整机防火墙策略。不关闭 Gatekeeper、SIP 或反作弊。

fork 使用不同应用 ID、配置目录、日志、单实例锁、自启名和更新通道。上游本地签名脚本会创建/调整钥匙串、信任配置并硬编码上游标识，不能未经审查直接运行。[S06][S08]

## 9. 已知风险与处理

| 风险 | 处理 |
|---|---|
| Windows 游戏仍接收部分后台 Raw Input | 保守焦点策略、失败留本地；可选实机记录，不承诺通吃游戏 [S11][S12] |
| Mac 接收进程被强杀时无法运行清理 | 不承诺 SIGKILL 后绝对释放；记录残余风险，不默认加特权守护进程 |
| Mac 本地键盘与远端同时按同一修饰键 | 账本只释放本次远端输入；同时输入仍需明确接管策略，不声称能完全隔离 OS 全局状态 |
| 连接恢复后迟到旧按键 | session/boot 标识、序号、终止不可复活 |
| 同时双向复制导致覆盖/回环 | 操作 ID、系统版本、来源与确定性冲突规则 |
| Mac 构建没有覆盖 Windows cfg 分支 | Windows 真实代码审查 + 可用原生 CI，状态独立记录 |
| 无 Apple/Windows 付费签名证书 | 提供本地测试产物与限制说明；不要求购买、不冒充签名公证 |
| 上游变化导致函数名不同 | 先生成源码映射，调整实施位置，不能把建议名称当现成符号 |

## 10. 分层完成定义

**开发完成**：范围内代码实现、可用自动化检查、Mac 构建、审查、文档和已知风险完成。适用的环境缺失项单独列出。

**Windows 构建完成**：必须有 Windows 原生构建日志和实际产物；不是 `cargo check` Mac 成功即可。

**实际使用验证**：由各项测试各自标记。Windows/LOL 未测不阻塞开发合并或预览包生成；已测失败则记录问题，不作通过宣传。

**公开发布**：是独立外部动作，需要用户明确授权，不由“生成本地安装包”自动推导。
