# Codex 启动与续接提示词

## 1. 使用

把交接包放进 Codex 可读工作区，选择你要使用的模型。下面的提示词不依赖一个虚构的 `5.6terra` 配置字段，也不会修改你的全局设置。

## 2. 首次启动提示词

复制下面整个代码块：

```text
请作为本项目的主实现代理，在我的 M4 Mac mini 上实际开始 MyKVM fork 改造。我已经确认本交接包的需求范围，请不要只重新输出一份计划或重复选型。你使用我当前在 Codex 中选择的 5.6terra；不要擅自修改全局模型或代理配置。

先找到工作区中的 handoff/（或已有仓库中的 docs/handoff/），读取：
00_交接说明.md
01_总体设计与需求规格.md
07_源码核验与参考资料.md
02_详细设计_状态机协议与代码改造.md
03_执行任务计划.md
04_测试与验收计划.md
05_Mac开发构建与交付操作.md
以及 taskboard.json、testcases.json、项目现有 AGENTS.md。

固定需求：
1. 使用方向是 Windows 物理键鼠 → M4 Mac mini；Windows 游戏、Mac 开发，两块显示器各自直连。开发主机在 Mac 不改变产品的输入方向。
2. 免费开源，只传输入和可选剪贴板，不引入视频流、付费依赖、驱动、游戏注入或反作弊规避。
3. 指定 Mac/返回 Windows/紧急返回；游戏模式关闭边缘切换并尽量不介入本地鼠标高频路径。
4. 可靠按键释放、双向原生剪贴板、中文设置、托盘/菜单栏、普通用户自启、低资源后台运行。
5. LOL 实机测试不是开发、合并或打包的硬关卡。没有 Windows/LOL 环境时用 Mac 自动化、假平台、协议回环及可用的 Windows 原生 CI 推进；实机项独立记录为 optional_not_run/pending_environment，不阻塞其余工作，也不能假称通过。

先执行 T00/T01：检查当前工作区与用户改动、读取真实源码、记录完整 SHA、核验依赖和可用构建。审查参考 SHA 是 bb5421fe1d4c0c8c72bb3f6c0c35f0a0f994209b，但不要为匹配文档回退我的已有工作树。无 GitHub 授权时先本地 clone 和开发，不能以 fork 未完成为由停止全部工作。

特别注意源码已有能力：QUIC stream 已经有独立任务/发送并发限制；Windows release 已有无控制台属性。先确认当前版本，保留已有修复，不照旧分析重复重写。传输的 TLS pinning 不自动等于双向应用授权；必须审查实际配对与入站注入路径。

实施方式：每次只做一个原子任务，明确范围、编写测试、修改代码，核对实际 git diff、退出码和证据后再进入下一任务。遵守已有项目审批规则。若实际存在 $sol-multi-agent-development，读取并按项目级约定调用；不存在就单主线程完成，不编造子代理已执行。不要并行改同一核心文件，不改 ~/.codex/AGENTS.md。

测试默认使用 FakeInjector/FakeCapture，不自动操作我的真实桌面或剪贴板；不要退出或杀掉当前帮助我控制 Mac 的 Deskflow/RustDesk。真实权限授权、安装覆盖、钥匙串/信任变更、敏感系统配置及公开发布须先征得确认。

持续维护 taskboard、PROGRESS、SOURCE_AUDIT、测试报告和决策记录。将“代码实现”“自动化结果”“Mac构建”“Windows构建”“实机效果”分开记录。Mac 编译成功不能代替 Windows cfg 编译；Windows代码必须真实实现，不留 TODO/stub 冒充完成。Windows CI 不可用不阻塞独立的 Mac任务；已执行测试失败则修复相应问题。

交付时给出真实修改文件/提交、已运行测试、实际生成的安装包路径与校验和、未验证清单和回滚说明。没有产物不要伪造路径，没有实机数据不要宣传绝对零GPU或保证LOL兼容。

现在先简要说明你读到的关键约束，然后开始 T00/T01 的实际检查与执行。只对真正缺失且会改变安全边界或当前任务正确性的信息提问，不要重新询问已经明确的需求。
```

## 3. 中断后续接提示词

```text
继续这个 MyKVM Mac 优先开发项目。先读项目 AGENTS、handoff/00、03、taskboard.json，以及最新 PROGRESS、SOURCE_AUDIT、TEST_REPORT、DECISIONS；检查实际 git status/diff，不能只相信上次摘要。

找出上次最后一个已审查任务及下一项依赖满足的原子任务，按已有审批约定继续实际修改、测试和审查。不重新选型，不一次性重写所有模块。

再次确认：LOL 实机测试可选，不是开发/合并/打包关卡；无 Windows/LOL 环境就独立标记 pending_environment/optional_not_run，继续不依赖该环境的工作。已知编译或安全错误必须如实处理，不能把 skip 记为 pass。

保留用户改动和当前控制 Mac 的工具；真实输入、安装/权限/钥匙串、公开发布等动作按授权边界执行。最后更新代码、证据、任务状态和剩余事项。
```

## 4. 子任务委派模板

```text
当前唯一任务：<Txx 标题>
已经批准的计划：<版本/相关任务>
必读文件：<需求、接口、源码路径>
允许修改：<明确文件/模块范围>
禁止修改：<用户改动、其他核心模块、系统设置>
前置接口与证据：<实际状态>
验证命令/用例：<真实可执行命令 + A/M/W/L ID>
环境限制：Mac主开发；Windows/LOL缺失项独立记录，不作为全计划关卡
完成产物：<代码、测试、报告>
停止条件：<真实安全/接口/用户冲突，不包含缺少LOL>
返回：实际diff摘要、命令退出码、证据路径、待验证项；不得只口头说完成
```

主线程拿到结果后必须查看真实 diff 和测试证据。子代理回复“完成”不自动改变 taskboard 的审查状态。
