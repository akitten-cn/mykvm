# MyKVM 双机键鼠共享改造：Codex 工程交接包

版本：2.0 · 编制日期：2026-09-07 · 开发主机：M4 Mac mini（Apple Silicon）

## 1. 本次要做什么

以 `XxMinor/mykvm` 为底座，制作免费、开源、不串流画面的软件 KVM 修改版。实际使用方向固定为：**键鼠物理连接 Windows，Windows 打游戏，M4 Mac mini 接收输入用于 Codex、终端和浏览器开发，两块显示器各自直连。** 开发代码、运行主要测试和生成 Mac 安装产物则在 Mac 上进行。

不要重新推荐远程桌面、付费 KVM 或硬件。不要把开发主机在 Mac 误解为需要将产品默认方向改成 Mac 控制 Windows。

## 2. 最高优先级的本次变更：CR-001

**LOL 实机测试不是开发、合并或打包的硬性关卡。**

用户明确准备在 Mac 上开发，因此本包取代旧《MyKVM_Fork_源码审查与改造任务书》中以 LOL 验证结果作为后续阶段前提的安排。

新的执行方式：

- 在 Mac 上进行源码核验、实现、纯逻辑/模拟测试、协议回环测试、Mac 编译和可用的本机测试。
- Windows 原生 CI 可用时运行 Windows 编译和非交互测试；不可用时记录 `pending_environment`，继续不依赖它的工作。
- Windows 桌面、双机和 LOL 的测试均单独记录，**LOL 一律为非阻塞可选验证**。
- 不能把“未测试”写成“通过”；不能因缺少 Windows/LOL 环境就放弃 Windows 实现，只留下空壳。
- 授权缺失、证书失效、关键队列溢出等仍必须阻止真实输入接管。这是程序安全约束，不是要求用户去运行游戏。

## 4. 交给 Codex 的方式

1. 下载并解压 ZIP，将其中 `handoff/` 放进一个工作区，例如 `~/Projects/mykvm-workspace/handoff/`。
2. 在 Mac 的 Codex 中打开 `mykvm-workspace`；使用你已经选定的 `5.6terra`。这个称呼由你在客户端中选择，不是本包虚构的 API 模型 ID。
3. 将 `06_Codex启动与续接提示词.md` 的“首次启动提示词”完整粘贴给 Codex。
4. Codex 先检查工作区，再在旁边取得源码或使用你已经存在的仓库。已有仓库时也可把包放入 `docs/handoff/`。

不需要你先手动运行全部环境安装命令。Codex 应先检查已有工具，避免重复安装、升级全局环境或覆盖正在使用的程序。

## 5. 交付状态不能混成一个“完成”

每个任务至少分别记录：

```text
implementation: todo / in_progress / done / blocked
review: pending / approved / changes_requested
verification:
  automated: not_run / pass / fail / pending_environment
  mac_build: not_run / pass / fail / pending_environment
  mac_runtime: not_run / pass / fail / pending_environment
  windows_build: not_run / pass / fail / pending_environment
  windows_runtime: optional_not_run / pass / fail
  lol_runtime: optional_not_run / pass / fail
```

不是每项测试都适用于每个任务，使用 `not_applicable` 时写明理由。`optional_not_run` 不是 `pass`，也不是全项目 `blocked`。

“代码与 Mac 预览包交付”不要求 LOL 实测；没有生成 Windows 安装包时，只能交付 Windows 源码、构建脚本/工作流及待办，不能编造 EXE 下载地址。没有任何实机游戏证据时，版本说明写“游戏兼容性尚待实际环境验证”，不写“保证不掉帧”。

## 6. 执行纪律

一个原子任务 → 查看真实 diff → 运行该任务可用测试 → 主线程审查证据 → 更新状态 → 再进入下一任务。

不要并行改同一核心文件，不要一次性重写整个项目。已有 `$sol-multi-agent-development` / 项目 AGENTS 约定时优先遵循；不存在时用单主线程顺序执行，不为此新增收费工具或修改用户全局 Codex 配置。已有流程若要求逐任务人工批准，仍按原流程执行，但不得重新加入 LOL 硬关卡。

## 7. 证据与约束

本包是设计与执行输入，不包含已修改的 MyKVM 源码、已创建的 GitHub fork、已编译安装包或已经通过的测试结果。

源码审查快照：`bb5421fe1d4c0c8c72bb3f6c0c35f0a0f994209b`。它是本次能够核验的提交，**不是“最新稳定版”保证**。Codex 必须读取完整本地源码并记录实际开发 SHA。已存在的工作树优先保护，不为匹配本包而回退用户代码。

重要修正：本次快照的 QUIC 发送循环已经采用非阻塞 datagram 和独立 stream 任务；Windows release 入口也已经设置无控制台属性。这两项是需要保留和验证的既有能力，不是从零新增任务。详见 `07`。

冲突处理：用户最新要求 → 本包需求/已批准决策 → 实际源码事实与 API 约束 → 旧任务书。源码事实决定“已经有什么”，不能替代用户的功能目标；设计和实际代码不一致时更新定位与最小实现方案，而不是伪造函数。
