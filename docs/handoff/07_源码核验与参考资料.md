## 3. 确认的源码事实

### 3.1 QUIC

`PROTOCOL_VERSION = 1`；调用方持有 `UnboundedSender<TransportCommand>`。`send_datagram` 的返回意味着入队/检查结果，不证明远端已注入。

`run_transport` 已有 `send_datagram_nonblocking` 与 spawned stream tasks，并限制发送 stream 并发。`spawn_stream_reader` 仍有逐连接接受流、另起任务并整流读取的路径，需要审查其接收上限和与新增持久输入流的分工。

`client_config` 校验固定证书且 `with_no_client_auth()`；持久证书与配对授权不是同一层。源码注释中某些“每次启动新证书”说明也可能落后于已经持久化的实现，不能优先相信注释而不看函数。[S02]

### 3.2 剪贴板

文本上限 256 KiB；RGBA 图片上限 32 MiB。Mac 文本由 `pbpaste/pbcopy` 子进程路径实现；图片使用 arboard 等路径。已经有空文本过滤，读取多个格式时也有策略与测试。[S03]

### 3.3 启动与构建

`main.rs` 已有 Windows release 无控制台属性和单实例检查。[S05]

`package.json` 包含 `lint`、`build`、`tauri:build`、`tauri:build:mac-arm` 等脚本；Mac ARM 脚本的目标是 app/dmg 并使用 `--no-sign`。[S09]

`Cargo.toml` 声明最低 Rust 1.89、Tauri/Quinn、macOS/Windows 条件依赖，并包含 Windows input-helper workspace；这不等于所有目标都能在 Mac 上直接完整构建。[S07]

`tauri.conf.json` 仍有上游 identifier、updater 公钥/endpoint、Windows NSIS hook 和默认隐藏窗口。fork 不能只改 UI 标题。[S06]

### 3.4 许可

仓库 LICENSE 是 MIT，包含 `mykvm contributors` 的版权声明。保留原 LICENSE 与必要声明；新增依赖和外部代码逐项核验，不把别的许可证实现直接复制后仍称只有 MIT。[S23]

## 4. T01 必须补齐的本地核验

- 同一完整 SHA 上的 `input.rs` 钩子、真实 ReleaseAll、键位、方向热键全调用链。
- `lib.rs` 配对请求/授权、网络接收解码到注入的通路、群组密钥与逐 peer 信任区别。
- 主窗口关闭/销毁后 Rust runtime 的所有权、单实例与退出条件。
- 所有辅助进程、Windows installer hooks、自启、updater 的实际入口。
- 原生 Mac text backend 能否直接复用依赖，线程限制及所需权限。
- 完整锁文件、构建脚本、Windows cfg 编译路径与 CI 当前状态。

完成后更新 SOURCE_AUDIT，不能把这一待核验清单直接改成“已通过”。
